SES待機期間中の自己学習リポジトリです。
Spring Bootの習得を目指します。

## 毎日の学習ログ

### 2026-09-11
* **やったこと**: 
  * *プロジェクトの立ち上げとCLI操作*:
    * Spring Initializrを利用し、MavenベースのSpring Bootプロジェクトを生成。二重ディレクトリの問題を cd コマンドで自己解決し、mvnw.cmd によるサーバー起動を実践。
  * *ルーティングと基本応答*:
    * @RestController と @GetMapping を使い、ブラウザからのリクエストに対して文字列を返す基本のAPI（/hello）を構築。
  * *オブジェクトのJSON自動変換*:
    * UserProfile クラスや ArrayList を作成。Getterを定義しておくだけで、Javaのオブジェクトが自動的にJSONのオブジェクト（{}）や配列（[]）としてフロントエンドに配信される仕組みを実装。
  * *HashMapを使った簡易DB検索API*:
    * 「もふ」「たま」「ぽん」といったペットの名前をキー、品種を値とする HashMap を構築。@PathVariable でURLから検索キーを受け取り、該当データを返す PetController を作成。
  * *エラーハンドリング*:
    * 登録されていないキー（例：「ポチ」）で検索された際の条件分岐を作成し、APIの堅牢性を確保。
  * *バージョン管理*:
    * 実装済みのコードを spring-study という適切な名前に変更し、GitHubへプッシュ完了。
* **気づき・他言語（LaravelやNext.js）との違い**
  * *ルーティングの集約（アノテーション）*:
    * Laravel（routes/web.phpで一元管理）やNext.js（ファイルやフォルダ構造がそのままURLになる）とは異なり、Spring Bootはクラスやメソッドの真上に @GetMapping("/pets/{name}") のように「目印（アノテーション）」を書くだけで完結します。処理とURLの対応がひと目でわかるのが特徴です。
  * *JSON生成のアプローチ（厳格さと自動化）*:
    * PHPの連想配列やTypeScriptのオブジェクトのように「直接JSONっぽい形を書く」のではなく、Javaでは「必ずクラス（設計図）を作り、Getterを用意する」という手順を踏みます。少し手間はかかりますが、「型」が絶対的に保証されるため、大規模開発でもバグが起きにくいという強みがあります。
  * *基礎文法と実務の直結*:
    * 今日学んだ ArrayList や HashMap が、単なるコンソールの文字遊びではなく、Web APIが返す「JSONの配列」や「データベースの代わり」としてそのまま機能することが体感できました。
