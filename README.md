### 2026-09-11
* **やったこと**: 
  * *プロジェクトの立ち上げとCLI操作*:
    * Spring Initializrを利用し、MavenベースのSpring Bootプロジェクトを生成。二重ディレクトリの問題を cd コマンドで自己解決し、mvnw.cmd によるサーバー起動を実践。
  * *ルーティングと基本応答*:
    * @RestController と @GetMapping を使い、ブラウザからのリクエストに対して文字列を返す基本のAPI（/hello）を構築。
  * *オブジェクトのJSON自動変換*:
    * UserProfile クラスや ArrayList を作成。Getterを定義しておくだけで、Javaのオブジェクトが自動的にJSONのオブジェクト（{}）や配列（[]）としてフロントエンドに配信される仕組みを実装。
  * *HashMapを使った簡易DB検索API*:
    * 「もふ」「たま」「ぽん」といったペットの名前をキー、品種を値とする HashMap を構築。@PathVariable でURLから検索キーを受け取り、該当データを返す PetController を作成。
  * *エラーハンドリング*:
    * 登録されていないキー（例：「ポチ」）で検索された際の条件分岐を作成し、APIの堅牢性を確保。
  * *バージョン管理*:
    * 実装済みのコードを spring-study という適切な名前に変更し、GitHubへプッシュ完了。
* **気づき・他言語（LaravelやNext.js）との違い**
  * *ルーティングの集約（アノテーション）*:
    * Laravel（routes/web.phpで一元管理）やNext.js（ファイルやフォルダ構造がそのままURLになる）とは異なり、Spring Bootはクラスやメソッドの真上に @GetMapping("/pets/{name}") のように「目印（アノテーション）」を書くだけで完結します。処理とURLの対応がひと目でわかるのが特徴です。
  * *JSON生成のアプローチ（厳格さと自動化）*:
    * PHPの連想配列やTypeScriptのオブジェクトのように「直接JSONっぽい形を書く」のではなく、Javaでは「必ずクラス（設計図）を作り、Getterを用意する」という手順を踏みます。少し手間はかかりますが、「型」が絶対的に保証されるため、大規模開発でもバグが起きにくいという強みがあります。
  * *基礎文法と実務の直結*:
    * 今日学んだ ArrayList や HashMap が、単なるコンソールの文字遊びではなく、Web APIが返す「JSONの配列」や「データベースの代わり」としてそのまま機能することが体感できました。

### 2026-09-14
* **やったこと**: 
  * *データの登録API（POST）の実装*:
    * @PostMapping と @RequestBody を使い、JSONデータを受け取って HashMap （簡易データベース）に追加する機能を作成した。
  * *受け取り専用クラスの作成*:
    * フロントエンドからのデータを受け止める専用クラス（PetRequest）を作成し、Javaの厳格な型ルールに則った安全なデータ受信を実装した。
  * *REST Clientによるテスト*:
    * VSCode拡張機能「REST Client」を導入し、api.http ファイルからPOST/GETリクエストを送信。ブラウザではできない「登録処理」の動作検証を行った。
  * *レイヤーアーキテクチャへのリファクタリング*:
    * 処理を「窓口（Controller）」と「ビジネスロジック（Service）」に分離。@Service を付与した PetService クラスにデータ処理を切り出し、実務標準の設計思想を適用した。
  * *トラブルシューティングの実践*:
    * ジェネリクス（``）の指定漏れによるコンパイルエラーや、PCのメモリ不足によるサーバー起動エラーに直面し、自力で解決した。
* **気づき・他言語との違い**:
  * *型（ジェネリクス）の厳格さと安全性*:
    * PHP（Laravel）やTypeScriptのようにリクエストデータを柔軟なオブジェクトや連想配列としてそのまま受け取るのではなく、Javaでは「受け取り専用クラス」を定義し、Mapのキーと値も `` と明確に指定する必要がある。記述量は増えるが、型不一致などのバグをコンパイル時点（実行前）で確実に防げる堅牢さを肌で感じた。
  * *アーキテクチャによる役割分担の美しさ*:
    * Controller（窓口）とService（厨房）を分けることで、各クラスの役割が極めて明確になった。LaravelなどでもService層を分けるアプローチはあるが、Spring Bootでは @Service などのアノテーションとDI（依存性の注入）によって、この連携が非常にスムーズに実現できることがわかった。
  * *API設計とテストツールの必須性*:
    * ブラウザのURL直打ち（GET）だけではPOST処理の検証ができないため、REST Clientのようなツールが不可欠であることを学んだ。また、作成した .http ファイルがそのまま「APIの使い方メモ（仕様書）」としてGitに残せるという実務的なメリットを体感できた。

  * *URLマッピングの厳密さ*:
    * Controllerクラスレベルでの @RequestMapping の有無により、エンドポイントが /pets になるか / になるかが変わる。テストコードを書くことで、自分のAPIのルーティングをより厳密に意識するようになった。
